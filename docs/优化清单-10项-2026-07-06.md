# 全站优化清单（10 项）+ 下单→生产→发货→物流 自动化闭环方案

日期 2026-07-06 · 基于代码审查（含最新 cart-sync / AI 售后 / Turnstile 修复）
目标：方便快捷、易操作、完成度高、稳定、**转化率优先**。

---

## 先回答核心问题：下单后能否自动生成生产工单？

**现在不能——这是闭环里唯一的手动断点。** 现状逐环审计：

| 环节 | 现状 | 自动化程度 |
|---|---|---|
| ① 辅助下单 | AI 客服 + 配置器 + 服务端核价 + Stripe | ✅ 全自动 |
| ② 订单创建 | 支付成功 → 订单入库 + 客户/商家邮件 | ✅ 全自动（含 webhook 兜底） |
| ③ **生产工单** | `work_orders` 表和打印页都有，但要**人工进后台点"生成工单"**，且订单状态 pending→in_production 也要人工点 | ❌ 手动 |
| ④ 发货单 | 后台 Shippo 选费率→买面单→tracking 写库→发货邮件 | 🟡 半自动（每单人工点 2-3 下） |
| ⑤ 物流追踪 | Shippo webhook：妥投自动把订单置 completed；游客可查单 | ✅ 全自动 |

**结论：补上③的自动化 + 简化④，闭环就成立。** 方案见文末。

## 十项优化（按转化影响 × 实施难度排序）

### 1. 商品页选项从「下拉框」改成「可视化选择器」 ⭐转化影响最大
现状：配置器所有选项（面料颜色、褶型、衬布、控制方式）都是原生 `<select>` 下拉框，客户看不到面料长什么样就要做决定。
做法：面料/颜色选项改为**色卡缩略图网格**（点选，选中高亮，图片来自后台上传的选项值图片）；褶型/款式配**简笔示意图**。这是定制窗帘电商转化的第一杠杆——客户"看见"才敢买。
涉及：`store/[id]/components/*.tsx` 共享一个 `OptionPicker` 组件；admin 选项值加 image_url 字段。工作量：中。

### 2. 商品页补齐三个信任要素
- **预计交期**："Ships in ~2 weeks · made in our LA workroom"（写死常量即可，后台可改）
- **评价展示**：评价系统已建好但商品页没渲染 — 把已审核评价挂到产品页底部 + 标题下加星级摘要
- **工坊实拍**："Handcrafted since 1984" + 1-2 张车间照片（已有素材）
定制品客单价高，犹豫期长，这三样是压单的关键。工作量：小。

### 3. 结算页开通 Apple Pay / Google Pay（一行配置的转化提升）
代码已用 Stripe PaymentElement + automatic_payment_methods，**只需在 Stripe 后台 → Settings → Payment methods 开启 Apple Pay 并验证 angel-drapery.com 域名**，移动端结算就出现一键支付。移动端定制品结算最容易流失在填卡环节。工作量：极小（纯后台操作）。
同场加映：开 Affirm/Klarna 分期（大额单利器），同样零代码。

### 4. 配置器「不确定就别流失」兜底交互
客户在配置器卡住（尺寸报错、算不出价、停留超 60 秒未加购）时，就地弹出一条温和提示："Not sure about measurements? → 免费测量指导（AI 客服）/ 订样品 / 约上门"。把即将流失的流量导进三个已建好的低门槛通道。工作量：小（一个共享 hook + 提示条组件）。

### 5. 商店页视觉与营销站统一 + 分类导航
现状：营销站是高级深色调，/store 是素白网格，观感断层；商品多起来后没有分类筛选。
做法：store 头部沿用品牌深色 hero 条；按产品线加分类 tab（Drapery / Roman / Roller / Hardware / Swatches）；商品卡加"from $XXX"起价角标（starting-prices API 已有）。工作量：中。

### 6. 【闭环核心】支付成功自动生成生产工单 + 自动进入生产状态
见文末详细方案。工作量：中，收益：每单省 3-5 分钟人工 + 零漏单。

### 7. 发货页一键化：预选最优费率 + 批量打单
现状发货页每单要手动选包裹/费率/购买。做法：按品类预设包裹尺寸模板（罗马帘/卷帘/窗帘杆各一套），进页面自动取默认费率，一个"Buy Label"键完成；多单待发货时支持勾选批量购买。`shipments` 表加 `label_cost` 顺手做运费对账。工作量：中。

### 8. 妥投后自动化两连发：邀评 + 安装指引
Shippo webhook 妥投时（现在只改状态）追加：(a) 立即发"安装指引 + 遇到问题点这里"邮件（带售后工单入口）；(b) 14 天后发邀评邮件（Vercel cron + `orders.review_invited_at` 字段防重）。评价反哺第 2 项的商品页展示，形成转化飞轮。工作量：小-中。

### 9. 上货流程模板化（后台建品向导）
现状建商品要手写 options/params JSON 风格结构，容易错 key（aapp_engine 接线更是如此）。做法：admin 建品页加"从模板创建"——选产品类型（Luma 卷帘 / 罗马帘 / 布帘 / 窗帘杆）即自动生成符合 `docs/aapp-engine-wiring.md` 约定的完整选项骨架 + aapp_engine 参数，管理员只填面料名和数值。配合商品草稿/预览状态一起做。工作量：中。

### 10. 稳定性：错误告警 + 每日运营摘要
现在出错只进 Vercel 日志，没人盯就不知道。做法：(a) 关键失败点（订单创建失败、核价 throw、Stripe webhook 失败、AAPP intake 失败）发告警邮件给 admin@（Resend 已有，包一个 `alertAdmin()` 帮手函数，各 catch 处调用）；(b) 每日 8am cron 发运营摘要：昨日订单数/金额、待生产、待发货、新咨询、AI 客服对话数。你不开后台也心里有数。工作量：小-中。

## 闭环自动化方案（第 6 项详细设计）

目标链路（全自动，人工只剩两个"确认"点）：

```
客户下单(AI辅助+配置器)
  → 支付成功 createOrder                          [已有 ✅]
  → 自动: work_orders 建行(含订单条目快照 version=1)  [新增 A]
  → 自动: 订单状态 pending→in_production + 客户"开始制作"邮件 [新增 B]
  → 自动: 工单 PDF/打印链接 邮件到车间邮箱 + 商家通知   [新增 C]
  → 车间生产完 → 后台发货页一键买面单(第7项)          [半自动 🟡→一键]
  → 自动: 发货邮件 + tracking                      [已有 ✅]
  → 自动: Shippo webhook 妥投→completed→邀评(第8项)  [已有 ✅ + 新增]
```

实施要点（给执行模型）：
- **A**：`lib/createOrder.ts` 订单 INSERT 成功后调用新函数 `autoCreateWorkOrder(orderId, items)`（放 `lib/workOrders.ts`）：INSERT `work_orders`（notes='auto-generated on payment'，items 快照进新列 `items_snapshot jsonb`——工单必须锁定下单时刻的配置，后续改单走 version+1）。失败绝不能影响订单（catch + alertAdmin）。
- **B**：同一处把订单状态直接置 `in_production` 并写 order_history（from pending, by 'system'）；复用现有状态邮件钩子。若你想保留人工审核一道闸（比如可疑单），改为"自动生成工单但状态留 pending，后台一键确认"——二选一，建议先全自动+告警兜底。
- **C**：`orderEmails.ts` 加 `sendWorkOrderEmail()`：邮件正文即工单内容（品类分组、尺寸、面料、选项、条目备注），收件人 `WORKSHOP_EMAIL` 环境变量（默认 admin@）。已有工单打印页 `admin/orders/work-order/[id]` 附深链。
- **风险控制**：swatch 单不生成工单（isSwatch 全单跳过，直接留 pending 走发货）；含 needs-review 商品（未来）可豁免。
- **验收**：测试卡下一单 → 不碰后台，应收到 3 封邮件（客户确认、商家通知、车间工单），后台订单已是 in_production 且工单可打印。
