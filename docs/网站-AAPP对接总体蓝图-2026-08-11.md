## 一、六大板块与边界(定稿,后续不重开讨论)

| # | 板块 | 职责 | 明确不做 |
|---|---|---|---|
| 1 | **3D 设计引擎** | 一切"准确的东西":尺寸链、褶皱、fullness、轨道位置、面料纹理比例。设计标准的唯一权威 | 不交给 AI 决定任何几何/尺寸/工艺参数 |
| 2 | **AI 图像增强** | 仅把 3D 出图变得更像照片(氛围示意按钮) | 不改面料花色、不作为最终效果依据 |
| 3 | **Handcrafted Drapery 产品线页** | 展示定制能力:款式/颜色大致效果(嵌部分 3D)、面料库入口、参考估价、request quote | 不承载直接下单付款 |
| 4 | **Online Store** | 4–5 个畅销标准款,流程极简,直接付款,全美发货 | 不做全品类铺开、不做复杂定制参数 |
| 5 | **面料库** | 挂在 Handcrafted Drapery 线:筛选、收藏、request swatch、输入尺寸得**参考估价**。数据完整的精选面料可即时估价,其余走 request quote | 不做全部商品化;前台不承诺最终价(报价/运费/安装/可用性以销售确认为准) |
| 6 | **销售跟进系统(AAPP)** | 客户提交后自动建档(尺寸+收藏面料+估价结果+备注)→ 分配销售。销售接手时已知道客户想要什么 | 网站不自建 CRM,一切档案落 AAPP |

上线顺序(Eddie 定):**结构分清 → 少量畅销款上线 → HD 页 + 部分 3D 演示 → 面料库 MVP(精选面料)→ 接销售软件 → AI 助手逐步加**。

## 三、双轨客户旅程与数据流

```
小单轨(标准款):
  Store(4-5 畅销款) → 配置(简) → 付款 → orders/work_orders
    → [已设计未建:C4 websiteOrder 推 AAPP WEB 卡,见 docs/DESIGN-C4-orders-into-aapp-2026-07-20.md,另行拍板]

大单轨(定制,本蓝图主线):
  HD 产品线页(3D 演示,理解定制能力)
    → 面料库(筛选/收藏/request swatch)
    → 输入尺寸 → 参考估价(数据完整面料即时;其余 request quote)
    → 收藏+尺寸+估价 存 设计档案(登录=项目;未登录=cookie/localStorage)
    → 提交(request quote / 预约咨询 / AI 聊天 handoff)
    → websiteInquiry(+design 字段) → AAPP 自动建档+分配销售+短信+跟进自动化
    → 销售接手:档案里已有 想要什么款式/面料/窗尺寸/看过的估价
```

估价免责铁律(贯穿所有出价面):**参考估价,最终报价、运费、安装、面料可用性以销售确认为准**。现 `PriceEstimator` 已有此措辞,后续统一为一处常量供全站引用。

## 四、数据契约

### 4.1 已有契约 —— 不动

- `websiteInquiry` 现有字段(name/phone/email/address/message/productType/intent/smsConsent/source/lang/appointment/website 蜜罐)照旧,兼容为先。
- `catalog_price_estimate`、`measureSheet`、luma-bands 同步:全部不动。
- 报价一致性军规:`packages/shared/src/pricing/aapp/` 引擎与 frozen tests 一个常量都不能动(AGENTS.md)。

### 4.2 新增:websiteInquiry 的 `design` 字段(阶段四实现)

网站侧提交时可选携带;AAPP CF 收到后写进客户档案(结构化备注块 + AI Sales Summary 摘要),老客户去重路径照旧追加:

```jsonc
{
  // …现有字段照旧…
  "design": {
    "windows": [            // 来源:面料库估价输入 / measure-wizard / 项目
      { "label": "Living room", "widthIn": 100, "heightIn": 96,
        "product": "drapery",              // drapery | roman | …
        "styleKey": "2fold_pinch", "lining": "LF", "composition": "fabric_only" }
    ],
    "fabrics": [            // 收藏的面料(精选库内为 code;库外为品牌+名称)
      { "code": "KAS-1234-05", "brand": "Kaslen", "name": "…", "tier": "mid" }
    ],
    "estimates": [          // 客户实际看过的数字,销售必须知道
      { "product": "drapery", "styleKey": "2fold_pinch", "lining": "LF",
        "pricedAt": "mid-range fabrics", "price": 1180,        // 或 rangeLow/rangeHigh
        "at": "2026-08-11T18:20:00Z" }
    ],
    "notes": "客户备注原文"
  }
}
```

原则:`design` 整体可缺省(向后兼容);数组各限长(如 windows≤10、fabrics≤20、estimates≤10)防滥用;AAPP 端只展示不参与计价。

### 4.3 面料库数据模型(阶段三实现)

- 布帘面料**另起一表**(如 `drapery_fabric_library`),不塞进现有 `fabric_library`(那张表是 $/sqm 的 Luma 底座,语义不同):
  `brand · pattern(面料名) · colorway code · price_per_yard · width_in · pattern_repeat_v/h_in · swatch_url · content(成分) · tags(颜色/材质/遮光) · is_curated(精选) · is_active`。
- 数据源:AAPP grouped JSON 一次性导入 + 定期同步(同 luma 同步思路:AAPP 是价格权威)。
- **即时估价门槛(三条件)**:`price_per_yard` 有值且稳定 + `width_in` 有值 + `swatch_url` 有图 → `is_curated=true`,前台显示估价;缺任一 → 只能收藏/request swatch/request quote。
- `pattern_repeat` 是 3D 贴图正确比例的前置(布不可拉伸、UV 按弧长),抓图管线建设时一并补录——面料库和 3D 共用这份数据,只建一次。
