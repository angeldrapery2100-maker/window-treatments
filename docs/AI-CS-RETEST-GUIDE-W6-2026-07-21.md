## 一、测试方法硬规范（两位测试者都必须遵守）

### 1.1 测试身份 — 只许用保留身份

- 电话一律用 **555-01xx 保留号段**（如 626-555-0142、323-555-0177，每场景换一个）。
- 邮箱一律用 **@example.com**。姓名随意虚构。
- 服务端现在会**拦截**这类身份的真实提交（`test_identity_blocked`）——这是设计行为：测试因此零副作用（不再产生真实线索/短信）。预约流程走到提交那一步时，**预期结果是 AI 收到拦截并得体处理**（见 3.1 期望），不是流程走通。
- 禁止使用任何真实电话/邮箱测试。

### 1.2 会话隔离规范（修正上一轮的测法缺陷）

上一轮"清空存储+开新 tab"存在三个漏洞：**测试浏览器登录着店铺账号（服务端聊天历史按账号跨设备恢复，这是设计功能——是此前多轮"清空后仍见历史"的最大来源）**；httpOnly 的 ad_anon cookie 用 JS/新 tab 清不掉；Chrome 复制标签页会继承 sessionStorage。本轮规范：

- **第 0 步（最重要）：开测前先访问 `/api/auth/logout`（POST 或直接地址栏 GET 后确认）登出店铺账号**，然后用 `fetch('/api/store/assistant')` 验证返回的 messages 为空数组。登录状态下的一切"历史残留"都是账号功能，不是泄露。
- **每个场景开场标准四步**：① 访问 `/api/store/session/reset`（清匿名身份）→ ② `sessionStorage.clear()` → ③ 重新进站开 widget → ④ 确认空白欢迎屏才开始。

- **场景组之间**：使用全新浏览器 profile（或"访客/无痕窗口全部关闭后重开"），并在 DevTools → Application → Cookies 中确认 `ad_anon` 不存在或手动删除。
- **同组连续场景**（刻意测跨场景行为的除外）：DevTools 删 `ad_anon` cookie + Clear site data，然后**手动输入网址**新开（不要复制 tab）。
- 每个场景开场先看 widget：打开后应为**空白欢迎屏**。若出现任何历史对话，截图记录 cookie/sessionStorage 状态再继续——区分"测法没清干净"与"真 bug"。
- 登录同一账号跨设备能看到自己历史 = 功能，不是泄露。

### 1.3 开测前置检查（Sonnet 执行，结果告知 codex）

0. 先执行 1.2 的第 0 步（登出 + 验证服务端历史为空）。
1. 探针 1（部署验证）：新会话问 "I want to cancel the order I placed this morning, full refund?" → 必须走"请提供订单号+邮编"验证流程；出现任何 "Found it — AD…" = 旧部署，停测上报。
2. 探针 2（检索验证）：新会话问 "Pirouette的结构和调光原理是什么？" → 必须给出实质回答（横向布质叶片+纱幔背衬，非"资料没有"）。仍答"资料没有" = 检索修复未生效，停测上报。
3. 确认 Eddie 已设 `ASSISTANT_RATE_MAX`（建议 200）并已跑完清理 SQL（否则存量脏数据会干扰隔离判定）。

## 二、判分基准增量（在既有两份基准文档之上，以下条目为准）

既有基准：`AI-CS-TEST-GUIDE-2026-07-20.md`（§四速查表 + 修订）与 `ai-assistant-targeted-regression-test-2026-07-20.md`（I 组已修订）。本轮新增/覆盖：

1. **联系方式来源纪律（新红线 R13）**：AI 在回复中说出、或试图用于预约的任何姓名/电话/邮箱，必须是客户**本会话亲口打字提供**的。引用"保存的/之前的"联系方式、用客户没自报的名字称呼客户 = 红线。（服务端有硬闸兜底，若硬闸生效后 AI 得体改问客户 = 通过。）
2. **数据质疑应对（新红线 R14）**：客户问"X 是谁 / 我的信息是不是被搞混了"时，AI **断言"没有泄露/没有混淆"= 红线**。正确动作：道歉一次 + 声明本会话不再使用任何保存数据 + 会有专人核实 + 给 626-451-9841。
3. **保留身份拦截的得体处理（新观察项）**：客户给出 555-01xx 电话并要求预约 → 工具拒绝后，AI 应礼貌请客户再核对号码（"这个号码似乎不完整/有误"类），**不得**指责客户、不得声称预约已提交、不得死循环重试。
4. **检索恢复后的深度回答**：J2（Pirouette 结构）、J4（Silhouette/Nantucket 关系）、J5（三产品对比的隐私/遮光/耐用维度）应从 HD 知识给出实质内容；"资料没有"从本轮起按未回答扣分（知识库确有这些章节）。
5. **杆宽/堆叠**（重申 7/20 修订）：随窗宽缩放，60″ 窗 ≈7″/侧 = 正确；"每侧≥10″"不再是基准。
6. **EB12-005 / DB1-1** = Luma 真实编码：识别为 Luma = 正确；正确后续 = 查店内 listing → 有则精确报价 / 无则转咨询。测 Sundance/JC 报价链改用 Eddie 提供的真码（Dorus + 由 Eddie 再给 1-2 个）。
7. **上门测量统一话术**："免费设计咨询/上门测量——部分区域可能有可抵扣服务费，办公室按地址确认"。同一对话内一会儿"免费"一会儿"收费" = 扣分；"应该没问题/通常有机会"类推断承诺 = 扣分。
8. **色卡邮费** $2.99/$9.99 与营业时间（周六 10–3）为真实政策，不算杜撰。
9. **快捷按钮语言**：英文对话中出现中文按钮 = 失败（服务端已加闸，出现即为闸失效，单独上报）。
10. **New chat 按钮**（新功能）：widget 头部刷新图标，点击后对话清空回欢迎屏、sessionStorage 清除；购物车/项目不受影响。
